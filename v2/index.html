蔡司镜片｜质量知识问答 + 数据查询 Agent

客户 / 行业
蔡司镜片 / 光学镜片
我的角色
系统切换项目经理助理、质量流程与数据治理顾问
时间
2025.01–2026.06
看交互 Demo ↗演示用示例数据

Demo 为基于项目场景自建的演示原型，数据为示例

问题

质量资料散在作业指导书、字段字典、月报、8D 案例里，新旧版本并存；检验批状态、不合格统计要依赖 IT 或关键用户查询。

做法

借 SAP 升级做质量知识治理，给文档补齐版本、状态、生效日期、适用工厂、责任人元数据；问题分为规则定义类（走文档 RAG，附来源和版本）与统计状态类（走数据查询 Agent，受控接口，返回数据时间和口径）；无有效依据时拒答并给出责任人；建评测集，Bad Case 按理解、检索、生成、工具、权限与数据逐层归因。

结果（定性）

修复了新旧两版作业指导书同时召回导致混入废止规则的问题（补齐元数据 + 硬过滤现行状态）；先在质量部关键用户中试点，反馈进入 Bad Case 池定期复盘。

万豪酒店｜采购平台规划与专家经验蒸馏 Agent

客户 / 行业
万豪酒店 / 酒店
我的角色
项目经理
时间
2026.06–2026.10
看交互 Demo ↗演示用示例数据

Demo 为基于项目场景自建的演示原型，数据为示例

问题

资深顾问陆续退休，品类策略、供应商评估和方案取舍的判断随人离开而流失；新人形成合格方案初稿周期长、返工多。

做法

七要素结构化访谈（背景、约束、备选方案、选择理由、被否掉的路线、后果、反例）→ 模型抽取案例草稿、顾问逐条校对 → 按品类、场景、客户规模、适用条件打元数据整案召回 → 生成初稿并逐条标注依据案例、关键假设和未决项 → 专家审核，修改原因回写案例库。

结果（定性）

制定初稿验收标准，达到专家认可标准的初稿才进入交付流程；先在项目组内试点。

问题

海外经销商和出海业务人员查车型/备件可用量、在途库存和清关状态，要在多个系统间切换或找内勤，响应慢且口径不一。

做法

在前端 CRM 上搭建库存查询 Agent：抽取物料、仓库、时间参数，缺参追问；校验权限后调用库存服务；数量和交期交给规则引擎与库存服务，模型不自行推算；只读，写操作一律转人工。

结果（定性）

以参数与结果正确率、追问是否恰当、越权拒答、端到端成功率建立评测用例，试点收集失败原因迭代。

关于我

保持好奇，创造下一种可能。

在德勤技术与转型团队做顾问和项目经理，从富士康的仓储系统、金赛药业的质量流程，一路做到蔡司的质量知识问答和数据查询 Agent、万豪的专家经验蒸馏 Agent。我习惯先把业务问题拆到流程、字段和规则这一层，再决定哪些交给模型、哪些交给规则和受控接口。现在想专注做 ToB 的 AI 产品：企业知识应用、Agent 和业务流程智能化。

我怎么做产品

  1. 懂行业、懂流程

    把一线业务问题拆到流程、字段和规则这一层。

  2. 分清模型和规则的边界

    模型负责理解表达、组织答案；数量计算、指标口径和业务承诺交给规则引擎与受控接口。流程固定的任务先用工作流，需要复杂决策再引入 Agent。

  3. 数据是企业 AI 的地基

    数据对象、口径、版本和责任人没理清，检索和查询一定会答错。

  4. 从方案走到实施

    调研、流程规划、功能设计、开发对接、测试、上线和推广培训。
