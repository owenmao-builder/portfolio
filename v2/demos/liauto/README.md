# 库存查询助手 · 简历项目演示

这是基于 Owen 简历中“理想汽车出海 FOB 前端 Agent CRM”项目场景自建的只读库存查询演示原型，所有数据均为虚构示例，不代表客户真实系统、数据或业务效果。

## 打开方式

双击 `index.html` 即可在浏览器打开。将 `index.html`、`style.css`、`app.js` 放在同一文件夹即可；不需要服务器、构建、联网或安装依赖。支持桌面与手机浏览器。页面不读取本地文件接口，全部示例数据内嵌在脚本中。

若放入个人网站，目录结构为 `demos/<name>/index.html`（同目录保留 CSS 与 JS）；左上角“← 返回作品集”链接指向 `../../index.html`。独立放置并打开时，点击会显示说明、留在当前页，不访问不存在的首页。

## 页面结构与操作

- 顶部固定显示“演示用示例数据”，滚动页面时始终可见。
- 左侧（手机顶部）切换两个虚构经销商与内部业务员，查看授权物料和仓库。“查看授权范围与规则”可展开或收起，手机默认收起。切换身份会清空会话及异常场景；内部业务员也不能写入库存。
- “交互演示”页签上方提供六个示例问题，也可手动输入。点击示例即开始查询，再点击下方“下一步”逐步展开；“上一步”与已到达的步骤可用于回看。
- 点击“演示模式 / 自动播放”从讲稿开场开始，自动设置经销商甲与正常返回，依次播放下方六段讲稿；完整约 2 分 50 秒，每个节点停留 3–9 秒，开场与评测按讲稿另设停留。控制条滚动时保持可见，点击“暂停演示”暂停，“继续演示”从当前画面恢复并重新计时当前段；结束后可重新播放。切到其他浏览器标签时自动暂停。
- 点击示例、步骤、页签、重置，修改问题、身份或返回场景等手动操作会退出自动播放；再次播放从讲稿开场开始。自动播放中的迪拜仓补充是固定讲稿动作，手动查询仍必须由用户选择。
- 在交互演示页使用键盘 `←` / `→` 切换上一步 / 下一步；第一步、最后一步和待澄清处遵守按钮相同边界。输入框、下拉框及带修饰键的操作不被接管。方向键操作会退出自动播放。
- 步骤详情带轻量过渡；系统开启“减少动态效果”（`prefers-reduced-motion`）时禁用动画和滚动过渡。
- 处理链路依次为问题分类、参数抽取、追问澄清、权限校验、库存服务、返回校验、组织答案。每步均展示输入、系统处理、输出和产品设计要点，并标明对应 Dify 节点。
- 缺参或歧义时在第三步暂停，点击聊天回复中的选项补充，一次问一项。条件未补齐时不能继续；配置与颜色是可选筛选项，多配置按记录分别返回，不进行合计。
- 输入时间为“最新”“今天”“当前”时，明确映射为本地“最新快照”，不是实时库存。也可输入 `2026-09-25` 等精确日期，未提供时间会追问。只有内置快照可被查到。
- 经销商甲可访问 L6、L9、制动片，以及天津港与迪拜仓；经销商乙可访问 L7、L8，以及上海港与阿拉木图仓。两个维度必须同时通过校验。提问不能改变会话身份。
- “陈旧数据”示例需要先切换到内部业务员。经销商甲查询该示例会被权限节点拦截，这同样是预期行为。
- 下方“库存服务模拟返回”可切换负数量、缺失单位、无效日期及服务不可用；切换后重新开始当前查询。建议使用正常查询示例演示返回值错误，查无记录时不会强行生成异常记录。
- “评测用例”页签展示四类评测口径与具体用例，点击“运行本地用例”运行同一套规则并显示逐条判定，不计算业务准确率。“载入演示”会设置对应身份、补充条件与异常场景，并从第一步开始展示。

## 数据来源与实现边界

事实来源为 `ref/resume_v1_final.md` 中的理想汽车项目描述，流程参考 `ref/PLAN.md`。本页面采用固定工作流进行模拟；没有接入 Dify、模型、客户系统或网络服务，也不等同于该方案已在生产落地。

`app.js` 内嵌 `ref/data/mock_inventory_SIMULATED.csv` 的虚构整车库存记录，保持原始数量、仓库、颜色和日期。为了保持界面中文，配置 Pro、Max、Ultra 分别显示为基础版、进阶版、旗舰版，仅为演示标签映射。车型名称是产品标识。额外添加一条虚构“制动片”备件记录，单位为件。清关、出关状态和用户授权表均为本演示补充，不来自原 CSV，也不表示真实项目内部信息。

原方案明确其轻量原型尚未实现用户权限校验。本演示按本次需求添加前端模拟权限规则，不能当作真实鉴权实现。真实鉴权必须在受控服务端执行，身份与授权不能由浏览器自行决定。

数量直接读取服务记录；不把在途加到可用、不自动修正异常数量、不推算未来库存或交期。最新快照可能已陈旧：演示基准日固定为 `2026-09-26`，早于该日三天以上提示陈旧，避免结果随打开日期改变。返回值需为非负整数，单位需匹配整车或备件，并包含有效日期；异常会阻断最终数量回答。零库存、查无记录与服务失败分别处理。清关与出关是独立的示例字段，不用于推断库存可售性或交期。

问题分类使用保守的本地关键词匹配，可能误拒含“交付”等词的只读问句，不能代表真实自然语言理解能力。预先生成模拟路径供逐步浏览；只有授权通过的路径才会读取内置库存。模拟写操作拒绝后仅展示人工处理建议，不创建工单，不执行调拨、锁库、修改数量或业务承诺。所有状态仅存在内存中，刷新即重置。

## 约 2 分 50 秒面试演示讲稿

自动播放与以下讲稿使用同一顺序；可以直接点击播放并按画面讲解，也可暂停后手动操作。时间轴为演示节奏，不是业务耗时或效果指标。

| 时间 | 自动播放实际画面 |
| --- | --- |
| 0:00–0:25 | 场景开场，示例数据标签、经销商甲、只读边界 |
| 0:25–1:10 | 正常查询：问题分类 → 参数抽取 → 追问澄清 → 权限校验 → 库存服务 → 返回校验 → 组织答案 |
| 1:10–1:40 | 缺参追问：问题分类 → 参数抽取 → 追问澄清 → 自动补充迪拜仓、再次展示澄清节点 → 权限校验 |
| 1:40–2:05 | 越权拒答：问题分类 → 参数抽取 → 追问澄清 → 权限校验；随后写操作拒绝：问题分类 |
| 2:05–2:30 | 正常查询问题 + 负数量返回：完整七步，重点停留返回校验与组织答案 |
| 2:30–2:50 | 评测用例页：先展示口径，再运行本地用例，结束播放 |


### 0:00–0:25｜交代场景与真实性

点击“交互演示”，保持“经销商甲”。指向顶部标签与左侧能力边界。

“这个页面是我基于简历中的理想汽车出海项目场景自建的演示原型，库存和用户都是虚构示例。场景是经销商与业务人员用自然语言查整车或备件库存。我在简历中描述的角色是流程规划与 CRM 方案顾问，这里重点演示查询路径和职责边界，不展示真实客户数据或未经验证的效果指标。”

### 0:25–1:10｜正常查询，讲清模型与服务边界

点击“正常查询”，先展示问题分类，再依次点击“下一步”：参数抽取 → 追问澄清 → 权限校验 → 库存服务 → 返回校验 → 组织答案。

“问题被拆成物料、仓库和时间等字段。必填参数明确后，同时核验经销商的物料与仓库权限，再读取服务。数量来自库存系统与规则引擎，模型不自行计算。这里可用十二台、在途八台均为示例。回答保留单位、更新时间、清关与出关状态，不用在途数量承诺交期。”

### 1:10–1:40｜缺参追问，不猜条件

点击“缺参追问”，两次“下一步”到追问澄清。点击“迪拜海外仓（虚构）”，再继续到权限校验。

“这次只给了车型和时间，系统先问仓库，不把经销商所在地猜成目标仓。一次问一个缺项，补齐后再执行查询。上方的歧义示例也会暂停，要求在天津与迪拜之间确认。”

### 1:40–2:05｜越权与写入边界

点击“越权拒答”，三次“下一步”到权限校验；再点击“写操作拒绝”，观察第一步输出。

“这个身份没有上海仓权限，所以库存服务不被调用，也不泄露数量。锁库与交期承诺在入口就被拒绝，解释业务责任并指向人工正式流程。内部用户也不能绕过本助手的只读边界。”

### 2:05–2:30｜返回异常，阻断错误答案

点击“正常查询”，下方模拟返回选择“异常：负数量”（自动播放会设置该场景），依次点击到“返回校验”与“组织答案”。

“权限通过不等于结果可信。工具返回也要校验：负数量、缺失单位或异常时间都应拦截，而不是让模型补一个看似合理的数字。服务失败和查无记录也不能回答成零库存。”

### 2:30–2:50｜评测收尾

点击“评测用例”→“运行本地用例”。

“简历中的评测方向是参数与结果正确率、追问是否恰当、越权拒答和端到端成功率。这里把它们落成可检查的本地示例用例，只展示逐条判定。真实项目效果数字尚待补充，不能从这份演示推断生产表现。”

## 面试可能追问 & 回答要点

1. **你在项目里具体是什么角色？**
   简历列为流程规划与 CRM 方案顾问，参与整车、备件、财经流程规划，明确订单、库存、发运、结算的数据来源和系统责任边界。具体交付物与负责范围仍需本人补齐证据，不把这份自建页面视为客户生产系统交付物。
2. **为什么不让模型直接算库存？**
   简历明确模型只理解表达、组织答案；数量计算、可用量口径与交期等业务承诺由规则引擎和库存服务处理。需要保证同一字段的口径一致，并保留数据更新时间。
3. **为什么不能顺手帮经销商调拨或锁库？**
   简历规定库存查询 Agent 只读，调拨、锁库、改数量、承诺交期一律不执行，识别后转人工并说明原因。读权限不意味着拥有库存写入或业务承诺权限。
4. **如何避免查错、越权或展示异常值？**
   按简历流程提取物料、仓库和时间，缺参或歧义追问；校验经销商授权后调用库存服务，再检查返回值，最终带数量、单位、更新时间和异常提示。本页只是这条流程的本地模拟。
5. **如何证明效果、如何迭代？**
   简历列出参数与结果正确率、追问是否恰当、越权拒答和端到端成功率，建立用例并收集查询失败原因、迭代抽取和追问话术。简历未提供已核实的用例规模、试点范围或效果数字，应明确待补，不报虚构成绩。
