# 质量流程从调研到系统落地

这是基于最终简历中“金赛药业 FDA 平台搭建”项目场景自建的静态演示原型，全部数据、记录编号、交付物内容和操作人员均为虚构示例。

**具体覆盖流程以面试口述为准，简历中待补。** 偏差、调查、纠正预防措施（CAPA）、有效性确认、关闭以及变更控制仅用于通用 FDA/GMP 质量流程示意，不是对客户实际系统、具体流程或交付成果的陈述。

## 打开方式

双击 `index.html`，用现代浏览器直接打开即可。请将 `index.html`、`style.css`、`app.js` 保持在同一文件夹。不需要服务器、构建、安装依赖或联网；没有外部字体、图片、接口，也不使用本地文件读取请求。

也可将整个 `out/` 的内容放在个人网站 `demos/<name>/` 中；左上角“← 返回作品集”使用普通相对链接 `../../index.html` 返回网站首页。单独打开 Demo 不会请求该链接；只有点击时才导航，若上两级没有首页，浏览器会显示文件不存在。

点击“演示模式 / 自动播放”从讲稿开头开始，每幕停留 8 秒，25 幕约 3 分 20 秒，结束后自动停止。**开始／重新演示会重置两条示例记录**；播放会自动填入虚构内容、勾选模拟签名并调用相同的校验与流转规则。可随时暂停／继续；切换后台标签页自动暂停。点击步骤、切换流程或编辑表单会暂停并进入手动操作，之后可“重新演示”。

键盘 `←` / `→` 等同当前部分的上一步／下一步；交付最后一步向右进入质量流程。流程内方向键只浏览节点，不提交记录；输入框、选择框及文本编辑区域内不接管方向键。页面支持系统“减少动态效果”设置。

## 页面结构与交互

- 顶部常驻“演示用示例数据”标签，并明确项目事实与演示边界。
- **项目交付全链路**：点击步骤条或上一步／下一步，依次查看业务调研、质量流程规划方案、系统配置、测试、上线落地。每步展示输入、处理规则、输出、示例交付物与产品设计要点。最后一步可进入质量流程模拟。
- **项目管理支持**：点击主计划、进度与风险、跨方协调，查看贯穿交付的示例管理动作。
- **质量流程交互模拟**：切换偏差与纠正预防措施、变更控制。每个节点展示角色、规则、预期输出和必填内容；点击“填入本节点示例”，检查内容，勾选模拟电子签名，再提交或审批。
- **异常路径**：留空提交会被必填校验拦截；切换错误角色会被权限校验拦截；未确认签名不能操作。从第二个节点起可填写驳回原因并签署，退回前一节点补充后重提。这里只检查内容非空，不自动判断业务证据是否真实、完整或有效。
- **浏览与流转分离**：点击步骤条或上一步／下一步只切换查看位置，不会跳过审批。只有当前待处理节点可执行操作；点击“返回当前待处理节点”继续办理。已关闭的记录只读。
- **审计追踪**：每次成功提交、审批、驳回均追加操作时间（本机时间）、模拟操作人、角色、签名含义、记录编号、状态变化、原签署内容及本次内容；可展开详情。驳回不会删除历史，重新提交会保留新旧内容。校验失败不会生成签署记录。
- 两个流程的状态在当前页面内存中独立保存；切换时保留业务草稿，但需重新确认签名。刷新清空全部记录；“重置当前示例”只清空当前流程。

## 事实边界与实现说明

事实来源为 `ref/resume_v1_final.md` 中金赛药业项目：项目经理助理、质量模块方案及实施顾问；参与主计划制定、进度与风险跟踪及客户质量部／开发／核心顾问协调；完成业务调研、质量流程规划方案、系统配置、测试与落地实施。简历记载实习入项后转正继续参与至收尾。

具体覆盖流程、职责划分、风险案例和交付结果仍待补。本演示没有补造这些事实，也没有业务指标或改善效果数字。参考目录未提供 `PLAN.md` 或 `data/`。

本项目属于传统咨询实施场景，本演示使用本地 JavaScript 显式状态机，没有人工智能推理、Dify 节点或网络调用。页面展示的通用流程规则都是为了说明“业务要求如何落成字段、角色与状态转换”而自建。

21 CFR Part 11 部分仅为电子签名与审计追踪通用概念示意，不是法规条款解读或合规实施证明：角色可以自由切换，签名是勾选确认，没有真实身份认证；日志位于内存中，可重置、不防篡改，也没有持久化、可靠时钟或正式系统验证。不能作为生产质量系统使用。

## 面试可能追问 & 回答要点

1. **你在金赛项目中是什么角色？** 简历为项目经理助理、质量模块方案及实施顾问；实习入项，转正后继续参与至项目收尾。不要扩大为独立负责全部平台建设。
2. **你经历了哪些交付环节？** 业务调研、质量流程规划方案、系统配置、测试与落地实施。具体覆盖流程简历仍待补，不能用本演示的偏差或变更控制代替实际经历。
3. **项目管理支持具体包括什么？** 参与制定主计划，跟踪进度与风险，协调客户质量部、开发与核心顾问。具体风险处理案例待补，不把页面中的角色待确认案例当作真实项目案例。
4. **哪些是你负责，哪些由其他人负责？** 简历仅明确上述角色和职责，详细责任边界仍待补。应依据真实经历说明自己的动作、协作方与最终决策方，不推断个人独立完成全部工作。
5. **项目成果或量化收益是什么？** 简历的交付结果仍待补，没有可引用的真实效果数字。本页只能说明流程落地的方法和交互原理，不能证明客户验收、合规通过或效率提升。
