# 专家经验蒸馏助手演示

这是基于 Owen 简历中万豪集中采购平台规划项目场景自建的演示原型，所有访谈、需求、案例与评分均为虚构示例，非客户真实数据。

## 打开方式

双击本目录的 `index.html`，即可在现代浏览器中使用。四个文件保持在同一目录即可；不需要服务器、构建、安装依赖或联网。

- `index.html`：页面骨架与始终可见的“演示用示例数据”标签。
- `style.css`：本地样式，适配笔记本和窄屏，使用系统字体。
- `app.js`：内置示例数据、本地规则、流程状态与交互。
- `README.md`：演示说明、面试讲稿与回答要点。

可将整个目录放在个人网站的 `demos/<name>/` 下；左上角“← 返回作品集”固定指向 `../../index.html`。单独打开不读取或检查首页文件，不影响演示；只有该目标存在时，返回链接才能打开作品集。

刷新页面或点击“重置本轮演示”会清空本轮修改、评分和回写。不写磁盘，也不调用任何网络接口。

## 页面结构与操作

顶部展示数据声明、项目场景和演示边界；左侧展示步骤条，右侧每一步都有输入、系统处理、输出、产品设计要点。使用“下一步 / 上一步”推进，已解锁步骤可直接点击。

### 演示模式与键盘

- 点击“演示模式 / 自动播放”从头播放并重置当前示例；每 6 秒推进一个步骤或执行一次讲稿操作。完整路径为甲 1–4 → 乙 1–6 → 案例库 C07，约两分钟，可按讲解节奏暂停。
- 按钮可暂停、继续；播放结束可重新播放。手动点击、编辑或切到后台会暂停，避免讲解中页面突然变化。
- 自动模式会代演抽取、七字段确认、入库、备件需求逐项补齐、示例审核与回写；页面明确提示代演，不能视为真实顾问校对或专家认可。
- 使用键盘 `←` / `→` 返回或前进；仍遵守校对、追问、检索与审核门槛，不会跳过未完成步骤。输入框、下拉框和文本编辑时保留方向键原有功能。
- 开启系统“减少动态效果”后关闭步骤动画。顶部数据声明在滚动时保持可见。

### 甲：经验沉淀

1. 查看模拟维修备件访谈与七要素提纲。
2. 点击“模拟抽取案例草稿”，查看七要素结构化结果。
3. 对照原文逐条校对，可编辑字段；每条均需勾选确认。修改已确认字段后，需要重新勾选。
4. 查看品类、场景类型、客户规模和适用条件；场景类型可调整，其余使用本示例固定标签。点击“确认元数据并入库”，将 C07 写入本轮案例库。

授权额度始终标为待确认，不能用虚构金额补齐。对已入库内容重新校对会撤销其本轮可召回状态，重新入库后才恢复。

### 乙：方案初稿生成

1. 点击布草、生鲜或缺信息的备件需求，可修改结构化选项。
2. 缺信息时按顺序逐项追问，补齐后才进入检索。
3. 按品类、覆盖范围和适用条件匹配，展示完整案例与排除说明。备件案例必须先走甲流程入库；无适用案例则暂停，不强行生成。
4. 查看逐条带案例依据、关键假设和未决项的初稿。
5. 操作者扮演专家，对“遵守客户约束、引用适用案例、指出缺失信息”逐项评分。可点击“填入示例修改意见”，再提交示例审核。任一不符合均阻止继续；处理修订后重新评分。三项均符合只是本演示的准入规则，并非真实客户验收门槛。
6. 点击“确认回写示例案例库”，在案例库展开引用案例，查看修改内容、原因与适用范围。回写为追加记录，不覆盖原案例；后续召回会携带该记录。

### 示例案例库

初始五个虚构案例：C01 布草、C03 生鲜、C04 供应商准入、C05 系统选型、C06 推广切换。甲流程入库后增加 C07 维修备件，共六个。每个案例包含七要素、四类元数据、判断规则、待确认项与修改记录。

资料来源：`../ref/resume_v1_final.md` 提供项目职责和流程的事实边界；`../ref/PLAN.md` 提供原型设计参考；案例与访谈基于 `../ref/data/` 中明确标注模拟的资料改编。未引用其中模拟的降本、耗时等成果数字，也未补写简历中的待补数字。原始资料未修改。

### 工作流节点映射与能力边界

页面为全中文，将 Dify 的 LLM 标为“大语言模型”。映射包括开始、分类器、参数提取器、条件分支、知识检索、代码校验、大语言模型、直接回复。人工校对、审核和回写是产品环节，真实集成需另行配置人工入口与接口；不宣称平台原生具备这些业务节点。

本地模拟只支持页面列出的结构化输入组合。访谈抽取是固定模板，检索是条件规则，初稿生成是文本模板；没有真实模型、向量检索、模型训练或模型微调，也不验证自由文本的语义。人工编辑后的案例仍需操作者保证准确；打分来自操作者，不是系统自动判断。界面上的评分数字均为明确标注的本轮示例值，不是准确率或业务成果。

### 0:00–0:25｜场景与边界

点击“甲 · 经验沉淀”的第一步，指向顶部标签。

“这个演示基于我简历中的万豪集采平台规划场景自建，所有数据均为虚构示例。业务问题是资深顾问的判断经验容易随人员离开而流失。我的设计目标是沉淀可追溯案例，辅助新人形成供专家审核的方案初稿。这里用本地规则演示流程，不代表真实项目运行效果。”

### 0:25–0:55｜保留专家的判断过程

点击下一步 → 模拟抽取 → 下一步；快速逐条对照、勾选七个字段；再下一步 → 确认元数据并入库。

“访谈围绕背景、约束、备选、选择理由、被否路线、后果和反例。以备件为例，不能只记下‘分层采购’，还要记录为什么否掉全部招标，以及特种设备不能套用的边界。原文记不清授权额度，就保留待确认。抽取后由顾问逐条校对，再按四类元数据入库。”

### 0:55–1:25｜缺信息先追问

点击“进入方案流程” → 选择“备件怎么采？（缺信息）” → 下一步。依次选择“跨区域多门店”“规范备件采购并保留应急能力”“普通备件，排除特种设备”，再下一步。

“需求先结构化，缺少覆盖范围、目标或适用条件就逐项追问，并保留已知信息。这里召回刚才入库的完整备件案例。整案包含反例与适用条件，不把孤立的一句话当成通用建议。”

### 1:25–1:55｜初稿可追溯

展开 C07 整案，再点击下一步查看初稿。

“初稿固定呈现方案要点、案例依据、关键假设与未决项。每条建议都可以追到案例。授权额度没有依据就继续留空待确认，不由模型补数字。布草和生鲜的策略不同，也是同样的道理：条件不匹配就不能套用。”

### 1:55–2:30｜专家准入与经验回写

点击下一步，将三项示例评分选为符合 → 填入示例修改意见 → 提交示例审核 → 下一步 → 确认回写 → 查看回写案例；展开 C07。

“验收看是否遵守客户约束、是否引用适用案例、是否指出缺失信息。这里由我扮演专家操作示例评分；只有本轮审核通过才继续。专家的修改内容和原因随适用范围回写案例库，给后续判断提供依据，但不替代下一次专家审核。”

### 2:30–2:45｜收束范围

保持案例详情展开。

“这个原型演示的是从访谈到案例，再到有依据初稿与专家反馈的闭环。真实业务指标和验收结果需要另外核实，这个页面不作效果承诺。”

## 面试可能追问 & 回答要点

1. **你在项目中负责什么？**
   - 按简历表述：作为项目经理负责集采平台规划交付，拆解调研、方案设计、评审主计划，协调采购、信息技术和核心顾问资源；牵头专家经验蒸馏流程。不要补写未确认的团队规模、调研范围或交付成效。
2. **为什么访谈要记录被否掉的路线和反例？**
   - 简历强调保留判断过程而非最终结论。这些字段说明决策取舍与适用边界，使新人知道什么情况下不应复用案例。
3. **为什么整案召回，还要给案例打元数据？**
   - 简历按品类、场景类型、客户规模、适用条件标记案例；整案召回附适用条件，避免断章取义。典型案例还可作为少样本示例，约束初稿结构和论证方式。
4. **怎么控制初稿胡编，并决定能否交付？**
   - 先追问缺失信息；结合采购规则生成，逐条标注依据、假设和未决项；专家按约束、案例适用性和缺失信息进行审核评分，达到专家认可标准后才进入交付流程。修改原因回写案例库。
5. **有没有真实量化成效？这里的分数能证明效果吗？**
   - 简历中的案例量、初稿耗时、专家通过率与交付结果仍待补充核实，不能用演示值代替。本页面的评分只用于展示审核交互，不代表真实使用数据或客户验收结论。

## 校验方式

在项目根目录执行 `node --check out/app.js` 检查脚本语法；确认 `out/index.html` 含精确文字“演示用示例数据”。交互验收关注：追问阻断、无适用案例阻断、七字段人工校对、专家不通过阻断、回写可查看、修改后准入失效、刷新恢复初始示例。

本轮通过 `node --check out/app.js` 与本地页面接口替身流程检查（包括暂停、键盘和播放状态）；未添加外部依赖、网络请求或本地 fetch。已尝试 1440×900 与 390×844 的 headless Chrome 截图，但 Chrome 启动被环境权限限制阻止（`Operation not permitted`），未产出图片，尚未完成真实浏览器视觉、横向溢出与控制台验收。日志保存在 `../_shots/`；接口替身检查不能替代浏览器验收。
