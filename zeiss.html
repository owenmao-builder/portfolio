02.2 / DECISION · 为什么选 A 不选 B
DECISION · 本地 bge-m3 vs 百炼通义
背景质量文档不能出内网，且需要秒级响应。
候选以百炼通义 text-embedding 为基线，在质量评测集上对比本地 bge-m3。
选择选本地 bge-m3 + bge-reranker 私有化部署：内网合规、延迟可控、不按调用付费。
结果文档 100% 不出内网，查询秒级返回。
DECISION · BM25 + 向量 vs 纯向量
背景料号、检验特性编号、SAP 字段名是精确词，纯向量容易漏召。
候选纯向量 / 纯 BM25 / 混合。
选择混合召回：BM25 管精确词，向量管口语，召回 Top-20、精排送 Top-5。
结果「检索未召回」类失分修复，种子集 75%→81.7%（多项共同贡献）。
DECISION · 轻量模型路由 vs 大模型路由
背景路由每次都要调用，大模型慢而贵、输出不稳定。
候选大模型 function 路由 / 规则 / 轻量模型。
选择轻量模型做分类与抽参，大模型只负责生成。
结果三链路分流，路由准确率 95%。
DECISION · Function Calling vs 模型读报表算数
背景不合格率、PPM 算错就是事故，而模型不擅长算数。
候选模型读导出报表 / NL2SQL 自由生成 / 受控接口。
选择Function Calling 调受控只读 SAP 接口，数值由代码计算，返回数据时间与口径。
结果编数字类错误 0，数字与 SAP 一致。
DECISION · 规则裁决 vs 让模型判断冲突
背景SOP、字段字典、8D 说法冲突时，模型会随机采信。
候选模型综合判断 / 按时间最新 / 按权威分层。
选择按「现行 SOP > 字段字典 > 8D」裁决，与质量部逐项对齐。
结果冲突类问题答案与质量部口径一致。
DECISION · 检索前过滤 vs 召回后排除
背景召回后再排除会挤占 Top-K，还可能漏网。
候选后置过滤 / 提示词约束 / 前置硬过滤。
选择废止版本在检索前硬过滤，只命中废止版本时拒答。
结果版本串味错误 6 条 → 0 条。
DECISION · 集成 SAP 原生 vs 重建质检模块
背景检验批、UD、通知单在 SAP QM 已有成熟事务，并与库存、审计联动。
候选在平台内重建 / 双写 / 只读集成。
选择SAP 原生不重建，Agent 只读集成并在其上提供依据与问数。
结果对 SAP 零写入，检验员在原有事务内即可获得依据。
DECISION · LLM 初评 + 人工复核 vs 纯人工
背景300 余条逐条人工评分成本高，纯 LLM 评分又可能偏宽。
候选纯人工 / 纯 LLM / 混合。
选择LLM 按准确/有据两维初评，人工复核校准。
结果每次改动可快速回归，全量约 92%。
💡 匹配场景优先于追求先进：每个选型都先回答「质量场景里答错的代价是什么」，再决定技术。

07.1 / 价值测算公式
显性节省 = 使用人数 × 查询频次 × 单次节省时间 × 人力成本
隐性价值 = 资深员工被占用的答疑工时 + 人员离职造成的知识断层风险
07.2 / 实际数据

资深员工答疑每天约 50 分钟被释放的隐性工时
